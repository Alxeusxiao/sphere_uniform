# 球面上 N 点均匀分布 —— 迭代优化 + 可视化

把"球面上 N 个点尽量均匀"这个模糊说法，落成**三个互相不同、但都严格定义**的优化目标，
并给出各自的迭代算法、精确度量、以及一个可以实时观看迭代过程的网页。

```
sphere_uniform/
├─ sphoptim.py            优化内核（纯 NumPy）：三类目标 + 全套迭代算法
├─ sphere_uniform.html    交互式可视化页面（可直接双击打开）
├─ make_data_par.py       批量求解（多进程），生成 sphere_data.json / sphere_data.js
├─ merge_chunks.py        合并分片、补算缺失的 N
├─ refine.py              对指定 N 做高强度 Tammes 重算（多起点 + 能量抛光）
├─ summarize.py           汇总实测质量，打印对照表
├─ kcenter.py             球面 k-center（最小化覆盖半径）局部搜索
├─ kcenter_escape.py      k-center 的逃逸候选（打破局部极小）
├─ cover_solver.py        覆盖目标统一求解器（多候选择优 + k-center）
├─ test_cover.py          覆盖目标回归测试（是否真的最小、是否命中已知最优）
├─ check_s_consistency.py 各 s 下能量与梯度的中心差分自洽性检验
├─ probe_s0.py            判定 s=0（对数能量）梯度系数的数值探针
├─ verify_s.js            前端各 s 的 Riesz 能量/梯度 vs Python 内核
├─ test_sphoptim.py       自检：与正多面体解析值、有限差分梯度逐项对照
├─ verify_js.js           前端 JS 与 Python 内核的交叉验证
├─ smoke_dom.js           用 DOM/canvas 桩真实执行页面脚本，检查渲染与迭代
├─ sphere_data.json/.js   预计算结果（40 组 N=4…200）
└─ README.md
```

## 1. 三类目标

| 目标 | 数学形式 | 极小/极大 | 直觉 |
|---|---|---|---|
| **能量最小**（Thomson / Riesz） | `E_s(P) = Σ_{i<j} ‖p_i−p_j‖^(−s)`，默认 `s=1` | min | 点与点互相排斥，系统松弛到能量最低的排布 |
| **最小间距最大**（Tammes / packing） | `d_min(P) = min_{i<j} angle(p_i,p_j)` | **max** | 任意两点不许靠太近；等价于把 N 个等大球冠塞进球面 |
| **覆盖半径最小**（covering） | `R_cov(P) = max_{x∈S²} min_i angle(x, p_i)` | min | N 个等半径球冠盖满球面，求最小半径 |

三者**不等价**，最优构型一般不同。例如 N=12：能量最优是正二十面体，
而覆盖最优是另一种准均匀构型（`d_min` 相同但覆盖更紧）；N=6 时能量最优近正八面体。

**Riesz 指数 `s` 可调**（网页里是下拉 + 数字框，命令行是 `-s/--riesz`）：

| s | 说明 |
|---|---|
| `s = 1` | 经典 Coulomb（Thomson 问题），也是预计算数据对应的取值 |
| `s = 0` | 对数能量（s→0 的极限），见下面的约定说明 |
| `s = 2` | 逆平方核 |
| `s = 3, 6, 12` | 更"硬"的核：点之间排斥衰减更快，更强调局部均匀性 |
| `s < 0` | 反向的核（更强调把点拉开） |

> **s = 0 的约定**（容易踩坑，代码里也写了注释）：
> 本项目的对数能量取 **`E_0 = 0.5·Σ_{i≠j} log(d_ij²) = Σ_{i<j} log(d_ij²)`**
> （有序对求和，与 `sphoptim.py` 的 `log(D2)/2` 求和逐位一致），
> 因此梯度是 **`∂E_0/∂p_i = 2(⟨p_i,A_i⟩p_i − A_i)`，`A_i = Σ_j d_ij^{-2} p_j`**。
> 这个 `2` 和符号都做过数值判定（`probe_s0.py`）与中心差分自洽性检验
> （`check_s_consistency.py`，各 s 的相对误差都在 1e-8 量级）。

与之配套的两个"间距"指标也一并给出：

* `min_angle(P)`：最小夹角（**最大**的点积对应最小夹角——这里很容易写反成"最大夹角"）。
* `second_min_angle(P)`：第二小夹角。含对跖点对的构型（正八面体、立方体、正二十面体…）
  最小夹角恒为 180°，此时只有第二小夹角有区分度。

## 2. 算法

全部算法都把点**约束在单位球面上**，且只做严格下降到/上升到球面的移动。

| 函数 | 目标 | 做法 |
|---|---|---|
| `thomson` | 能量最小（任意 s） | 球面 Frank–Wolfe：线性子问题给方向 `S=−G/‖G‖`，再对 `t∈[0,1]` 用"多点采样 + 三分细化"搜真实能量最小的步长（沿线能量不保证单峰，所以不用黄金分割） |
| `pgd_energy` | 能量最小 | 球面投影梯度下降 + 回溯线搜索（对照实现） |
| `tammes` | 最小间距最大 | `d_min` 的**次梯度上升**：对当前最紧的点对求和切向排斥方向，步长有界并自适应，附随机重启 |
| `solve_cover` | 覆盖半径最小 | **候选择优 + k-center 局部搜索**：把能量/Lloyd/Tammes/k-center 各自的解都用精确 `R_cov` 评估，取最小者 |
| `coverage_lloyd` | （对照实现） | 球面 Lloyd：把每个点移到 Voronoi 胞腔质心。它最小化的是**均方距离**（k-means），**不等价于覆盖半径**（k-center），所以只作为候选之一 |
| `voronoi_cells` | 几何 | 球面 Voronoi 胞腔的**精确**顶点（见下） |
| `coverage_radius` | 度量 | **精确**覆盖半径（见下） |

### 精确的球面 Voronoi / 覆盖半径

胞腔就是若干半球的交：

```
cell(i) = { v ∈ S² : ⟨v, p_j − p_i⟩ ≤ 0,  ∀j }
```

顶点 = 两张约束大圆的交点 = `±normalize((p_j−p_i) × (p_k−p_i))`，再按全部约束筛选
（一对对跖候选里恰有一个落在胞腔内）。

覆盖半径只需要检查每个胞腔的**顶点与棱中点**：最近点映射在每个胞腔内就是"到 p_i 的
球面距离"，它在球面凸多边形上的最大值必在顶点或棱上取得。于是

```
R_cov = max over cells, over (vertices ∪ edge midpoints)
```

**两个踩过的坑**（都写进代码注释了）：

1. 不能用切平面参数化求胞腔顶点。球面到切平面的正交投影**不保持大圆结构**，
   平面里的"两直线交点"投回球面并不是两条球面大圆的交点。此外切平面只能表示
   距 p_i 90° 以内的方向，而真实胞腔可能跨过 90°（正四面体的胞腔直径就是 180°）。
2. 顶点候选必须**同时生成 ± 两个符号**。只取一个符号会漏掉大约一半顶点
   （正二十面体胞腔会从 5 个顶点掉到 2 个）。

### 覆盖目标：为什么不能只用球面 Lloyd

`R_cov(P) = max_x min_i angle(x, p_i)` 是 **k-center**（最小化**最大**距离）目标，
而球面 Lloyd 最小化的是 **均方距离**（k-means）。两者不等价，实测差别很大：

| N | 旧：只用球面 Lloyd | 新：候选择优 + k-center | 改善 | 球冠面积下界 |
|---|---|---|---|---|
| 4 | 70.5288° | **70.5288°**（命中正四面体最优） | 0 | 60.0000° |
| 6 | 54.7356° | **54.7356°**（命中正八面体最优） | 0 | 48.1897° |
| 12 | 37.3774° | **37.3774°**（命中正二十面体最优） | 0 | 33.5573° |
| 20 | 31.1164° | **30.0942°** | +1.02° | 25.8419° |
| 40 | 22.8669° | **21.2952°** | +1.57° | 18.1949° |
| 60 | 18.4604° | **17.3029°** | +1.16° | 14.8351° |
| 100 | 14.4389° | **13.7387°** | +0.70° | 11.4783° |
| 200 | 10.3332° | **9.4348°** | +0.90° | 8.1096° |

修正前有一个很明显的症状：40 组里有 **21 组**的 `cover` 构型，其 `R_cov` 反而不是
三个目标里最小的，甚至比 `energy` 构型还差——这说明当时"覆盖目标"并没有真的在
最小化覆盖半径。

现在的 k-center 局部搜索：

* 每个 site 取自己 Voronoi 胞腔内**并列最远**的顶点/棱中点的**平均方向**作为移动方向。
  用"单个最远点"是不行的：正八面体/正二十面体本身已是局部最优，朝单个顶点移动
  会破坏对称性（实测 `R_cov` 从 54.736° 恶化到 73°）；取平均时并列方向互相抵消，
  于是能正确判定"已到局部最优"并停住。
* 每一轮扫描后用**精确 `R_cov` 做整轮回退**，因此 `R_cov` 单调不增。
* 卡在局部极小时用逃逸候选（单点最远方向扰断 / 一步 Lloyd / 一步能量精修），
  仍然只用精确 `R_cov` 判定是否采纳。
* 最后把所有候选（能量多起点、Tammes、Lloyd、k-center）统一评估取最小——
  所以 `sphere_data.json` 里 `cover` 的 `R_cov` **有保证**不差于任何被评估的候选。

回归测试见 `test_cover.py`：检查小 N 是否命中可解析最优、是否每组 `cover` 都最小、
以及 `R_cov` 是否都不低于球冠面积下界 `arccos(1-2/N)`。

## 3. 正确性自检

```bash
python test_sphoptim.py        # 全部通过
node verify_js.js              # 前端 JS 与 Python 内核一致
node smoke_dom.js              # 页面脚本运行时检查全部通过
python test_cover.py           # 覆盖目标回归测试
python summarize.py            # 打印实测质量对照表
```

自检覆盖：

* **解析值对照**：正四面体/正八面体/正二十面体/立方体的覆盖半径与最小夹角，
  以及 Voronoi 胞腔顶点数（3/4/5/3）。
* **梯度对照**：`riesz_energy` 的解析梯度与中心差分逐点对照（相对误差 < 1e-8），
  `d_min` 的次梯度同样对照。
* **已知最优值**：Riesz s=1 能量（N=4…20）与 Tammes 最优夹角（N=4…24, 32）的达成率。
* **覆盖优化单调改善**：Lloyd 迭代必须让精确 `R_cov` 下降，并与 30 万点细网格
  给出的下界比较（下界应略小于精确值）。
* **边界情形**：N=1,2,3（退化胞腔为半球，`R_cov` = 90°）不抛异常。
* **前端一致性**：`verify_js.js` 把页面里的数学函数抽出来，与 Python 内核在
  全部数据上逐项比对（能量/夹角/覆盖半径/梯度/胞腔顶点数）。
* **页面运行时**：`smoke_dom.js` 用 DOM+canvas 桩真实执行整段页面脚本，
  包含 boot、首次渲染、三种迭代算法、着色/网格/球冠分支与全部交互回调
  并断言**拖动旋转 / 滚轮缩放 / 窗口缩放都会触发重绘**，且同一帧的请求被合并成一帧。

实测质量（python summarize.py 汇总 sphere_data.json，共 40 组 N=4…200）：

## 4. 用法

```bash
# 求解若干 N（同时给出三类目标），输出 JSON
python sphoptim.py 6 12 20 -o out.json

# 生成网页用的完整数据集（覆盖 4–200 的一组常用取值）
python make_data_par.py
```

浏览器打开 `sphere_uniform.html`：

* **点数 N**：滑块 4–2000，另有"自定义 N"输入框（可到 20000，回车或点"生成"）。
  有预计算数据的 N 直接用最优解，没有的就用斐波那契格点做初值；
* **目标**（能量/间距/覆盖）与**来源**（预计算解 / 斐波那契初值）；
* **指数 s**：下拉选 1 / 0（对数）/ 2 / 3 / 6 / 12，也可直接填任意数值（−20…50）。
  注意预计算数据是 `s=1` 的解，切到别的 s 后需要自己迭代（界面会提示）；
* **单步 / 推进 n 步**：`单步 ▸` 只走一轮，右侧可填步数后点"推进 n 步"一次走多轮
  （手动推进时会先暂停自动循环，方便逐步观察点的移动）；
* **开始迭代**后可实时看到算法把点重新分布，三种算法都能在浏览器里跑：
  Frank–Wolfe（能量）、次梯度上升（间距）、球面 Lloyd（覆盖）；
* 实时指标：能量 `E`、最小夹角 `d_min`、覆盖半径 `R_cov`（前端实现了同一套球面
  Voronoi，因此是精确值；N>400 时自动改用格点估计并显示 `≈`），并画出迭代曲线；
* 着色可选"最邻点距离"或"Voronoi 胞腔面积"——均匀分布时着色应接近一致；
* 可叠加显示 ±`R_cov` 的覆盖球冠，直观看出"覆盖"与"间距"两种均匀性的差别；
* 拖动旋转 / 滚轮缩放都是**实时重绘**（按需 rAF 调度，同一帧内多次请求合并成一帧）。

### 保存 / 加载

| 方式 | 说明 |
|---|---|
| **保存到文件** | 下载当前点集为 JSON，含名称、N、目标、**Riesz 指数 s**、算法、迭代次数、指标与 `points: [[x,y,z],…]` |
| **从文件加载** | 文件选择器读入 JSON 或 CSV；也支持把文件**直接拖到画布/侧栏** |
| **存入收藏夹** | 存进浏览器 `localStorage`（同名覆盖），可列表、加载、删除、清空 |

加载端做了宽松兼容与校验：

* 接受本页面导出的对象、`{points:[…]}`、裸数组 `[[x,y,z],…]`、`{x,y,z}` 对象数组、CSV/空白分隔三列；
* 每个点都会**归一化到单位球**，非法点（长度为零、非数值、维度不足）自动丢弃；
* 全部非法或有效点少于 2 个时**拒绝加载并保持原状态**，不会把画布清空。

> `sphere_uniform.html` 通过 `fetch` 读 `sphere_data.json`；直接双击（`file://`）打开时
> 浏览器会拦截 fetch，此时自动回退到 `make_data_par.py` 一并生成的 `sphere_data.js`，
> 因此**单文件双击即可用**（保存/加载功能不依赖网络）。

## 5. 复杂度

* 能量/`d_min` 及其梯度：`O(n²)`。
* `voronoi_cells`：`O(n²)`（每个 site 只跟最近的 `k_nbr` 个邻居配对）。
* `coverage_lloyd` 每次迭代：`O(n²)`～`O(n³)`；N=60 约 10 s，N=100 数十秒。
* make_data_par.py 对大 N 自动减少 Lloyd 轮数（N≤40 用 200 轮，N=200 用 45 轮），
  否则 N=200 单组要十几分钟。
* 前端：N≤300 时能量/间距迭代可 60 fps；Lloyd 走 3000–8000 个斐波那契格点的
  离散版本，用来实时演示覆盖优化。
* 前端的大 N 优化（N=900 实测单步耗时）：

  | 环节 | 优化前 | 优化后 | 做法 |
  |---|---|---|---|
  | Frank–Wolfe 一步 | 1796 ms | **274 ms** | 线搜索的候选 t 与细化次数随 n 递减（每次候选都要一次 O(n²) 能量） |
  | Lloyd 一步 | 20066 ms | **68 ms** | 迭代中只算格点覆盖半径；精确 R_cov 是 O(n³)，不能放进每步 |
  | 渲染 | — | — | 网格采样数、点半径、逐点描边、着色方式按点数自适应 |

* 因此前端把"精确 R_cov"限制在 N≤400；更大的 N 用斐波那契格点估计（界面显示 `≈`）。

## 6. 主要参数

| 参数 | 含义 |
|---|---|
| `s` | Riesz 指数，`s=1` 为经典 Coulomb，`s=0` 为对数能量（网页里可实时切换） |
| `iters_energy` | 能量 FW 迭代轮数（每轮一次线搜索，收敛很快，默认 400） |
| `iters_tammes` | 次梯度上升步数（默认 8000） |
| `iters_cover` | Lloyd 迭代步数（默认 200） |
| `k_nbr` | Voronoi 胞腔构造时取的邻居数（默认 14，足够覆盖所有胞腔顶点） |
| `restarts` | 随机重启次数，用于跳出局部极小 |
| `EXACT_COVER_MAX`（前端常量） | 精确算 R_cov 的点数上限，默认 400，超过则用格点估计 |
