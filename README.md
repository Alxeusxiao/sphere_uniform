# 球面上 N 点均匀分布 —— 迭代优化 + 可视化

把"球面上 N 个点尽量均匀"这个模糊说法，落成**三个互相不同、但都严格定义**的优化目标，
并给出各自的迭代算法、精确度量、以及一个可以实时观看迭代过程的网页。

```
sphere_uniform/
├─ sphoptim.py          # 内核：球面几何 + 精确 Voronoi/覆盖半径 + 三类目标的算法
├─ sphere_uniform.html  # 交互页面（单文件，双击即用；内嵌同一套数学的 JS 版）
├─ make_data.py         # 数据集生成：多进程 + 断点续跑 + 合并 + 汇总
├─ tools.py             # 辅助命令：summary / refine / reference
├─ test.py              # Python 全量自检与回归（解析值、梯度、三类目标、覆盖回归）
├─ verify_frontend.js   # 前端检查：math（与内核逐项比对）+ page（页面行为）
├─ sphere_data.js       # 预计算结果（40 组 N=4…200，页面离线用）
└─ tests/reference.json # 前端交叉验证的参考值（由 tools.py reference 生成）

> 从 15 个可执行文件精简到 8 个：kcenter 三件套并入内核、数据脚本四合一、
> 三个 Python 测试合一、四个 JS 检查合一（共用一套 DOM 桩），并删掉了
> 重复的 sphere_data.json（内容与 .js 相同）。
```

## 1. 四类目标

| 目标 | 数学形式 | 极小/极大 | 直觉 |
|---|---|---|---|
| **能量最小**（Thomson / Riesz） | `E_s(P) = Σ_{i<j} ‖p_i−p_j‖^(−s)`，默认 `s=1` | min | 点与点互相排斥，系统松弛到能量最低的排布 |
| **最小间距最大**（Tammes / packing） | `d_min(P) = min_{i<j} angle(p_i,p_j)` | **max** | 任意两点不许靠太近；等价于把 N 个等大球冠塞进球面 |
| **覆盖半径最小**（covering） | `R_cov(P) = max_{x∈S²} min_i angle(x, p_i)` | min | N 个等半径球冠盖满球面，求最小半径 |
| **面积最均匀**（Voronoi 等面积） | `cv(P) = std(A_i)/mean(A_i)`，`A_i` 为第 i 个 Voronoi 胞腔的球面面积 | min | 每个点分到的球面面积尽量相等——最贴近"均匀"的直觉 |

四者**不等价**，最优构型一般不同。例如 N=12：能量最优是正二十面体（同时面积最均匀，
`cv≈0`），而覆盖最优是另一种准均匀构型；N=6 时能量最优近正八面体。

> 关于面积目标的一个实测结论：**斐波那契格点在面积均匀度上本来就接近最优**
> （n=100/200 时几乎所有算法都改善不了它），但在小 N（如 n=20）用能量解当起点
> 能把 `cv` 压低约 34%。所以 `solve_area` 采用的是"多候选 + 按 cv 择优"，
> 而不是单纯跑加权 Lloyd。

**Riesz 指数 `s` 可调**（网页里是下拉 + 数字框，命令行是 `-s/--riesz`）：

| s | 说明 |
|---|---|
| `s = 1` | 经典 Coulomb（Thomson 问题），也是预计算数据对应的取值 |
| `s = 0` | 对数能量（s→0 的极限），见下面的约定说明 |
| `s = 2` | 逆平方核 |
| `s = 3, 6, 12` | 更"硬"的核：点之间排斥衰减更快，更强调局部均匀性 |
| `s < 0` | 反向的核（更强调把点拉开） |

> **s = 0 的约定**（容易踩坑，代码里也写了注释）：
> 本项目的对数能量取 **`E_0 = 0.5·Σ_{i≠j} log(d_ij²) = Σ_{i<j} log(d_ij²)`**
> （有序对求和，与 `sphoptim.py` 的 `log(D2)/2` 求和逐位一致），
> 因此梯度是 **`∂E_0/∂p_i = 2(⟨p_i,A_i⟩p_i − A_i)`，`A_i = Σ_j d_ij^{-2} p_j`**。
> 这个系数和符号都做过数值判定与中心差分自洽性检验
> （`python test.py` 的"梯度自洽"一节，各 s 的相对误差都在 1e-8 量级）。

与之配套的两个"间距"指标也一并给出：

* `min_angle(P)`：最小夹角（**最大**的点积对应最小夹角——这里很容易写反成"最大夹角"）。
* `second_min_angle(P)`：第二小夹角。含对跖点对的构型（正八面体、立方体、正二十面体…）
  最小夹角恒为 180°，此时只有第二小夹角有区分度。

## 2. 算法

全部算法都把点**约束在单位球面上**，且只做严格下降到/上升到球面的移动。

| 函数 | 目标 | 做法 |
|---|---|---|
| `thomson` | 能量最小（任意 s） | 球面 Frank–Wolfe：线性子问题给方向 `S=−G/‖G‖`，再对 `t∈[0,1]` 用"多点采样 + 三分细化"搜真实能量最小的步长（沿线能量不保证单峰，所以不用黄金分割） |
| `pgd_energy` | 能量最小 | 球面投影梯度下降 + 回溯线搜索（对照实现） |
| `tammes` | 最小间距最大 | `d_min` 的**次梯度上升**：对当前最紧的点对求和切向排斥方向，步长有界并自适应，附随机重启 |
| `solve_area` | 面积最均匀 | 多候选（斐波那契/能量/对数能量/k-center/Tammes）+ 面积加权 Lloyd 抛光，按 `cv` 择优 |
| `area_lloyd` | 面积最均匀 | 朝胞腔质心移动，权重 `w_i ∝ Ā/A_i`，整轮 `cv` 回退保证单调不增 |
| `solve_cover` | 覆盖半径最小 | **候选择优 + k-center 局部搜索**：把能量/Lloyd/Tammes/k-center 各自的解都用精确 `R_cov` 评估，取最小者 |
| `coverage_lloyd` | （对照实现） | 球面 Lloyd：把每个点移到 Voronoi 胞腔质心。它最小化的是**均方距离**（k-means），**不等价于覆盖半径**（k-center），所以只作为候选之一 |
| `voronoi_cells` | 几何 | 球面 Voronoi 胞腔的**精确**顶点（见下） |
| `coverage_radius` | 度量 | **精确**覆盖半径（见下） |

### 精确的球面 Voronoi / 覆盖半径

胞腔就是若干半球的交：

```
cell(i) = { v ∈ S² : ⟨v, p_j − p_i⟩ ≤ 0,  ∀j }
```

顶点 = 两张约束大圆的交点 = `±normalize((p_j−p_i) × (p_k−p_i))`，再按全部约束筛选
（一对对跖候选里恰有一个落在胞腔内）。

覆盖半径只需要检查每个胞腔的**顶点与棱中点**：最近点映射在每个胞腔内就是"到 p_i 的
球面距离"，它在球面凸多边形上的最大值必在顶点或棱上取得。于是

```
R_cov = max over cells, over (vertices ∪ edge midpoints)
```

**三个踩过的坑**（都写进代码注释了）：

1. 不能用切平面参数化求胞腔顶点。球面到切平面的正交投影**不保持大圆结构**，
   平面里的"两直线交点"投回球面并不是两条球面大圆的交点。此外切平面只能表示
   距 p_i 90° 以内的方向，而真实胞腔可能跨过 90°（正四面体的胞腔直径就是 180°）。
2. 顶点候选必须**同时生成 ± 两个符号**。只取一个符号会漏掉大约一半顶点
   （正二十面体胞腔会从 5 个顶点掉到 2 个）。
3. 球面多边形面积**不能**用 `Σ 2·atan2(|u×w|, u·w)` 这种平面写法：实测正二十面体
   一个胞腔会算成 7.30（正确 2π），总面积会算成 87.6 而不是 `4π`。正确做法是
   **球面盈余 = 内角之和 − (m−2)π**；换用之后象限三角形 = π/2、二十面体 12 个胞腔
   各 `4π/12`、任意点集的总面积恒等于 `4π`（`test.py` 里有对应断言）。

### 覆盖目标：为什么不能只用球面 Lloyd

`R_cov(P) = max_x min_i angle(x, p_i)` 是 **k-center**（最小化**最大**距离）目标，
而球面 Lloyd 最小化的是 **均方距离**（k-means）。两者不等价，实测差别很大：

| N | 旧：只用球面 Lloyd | 新：候选择优 + k-center | 改善 | 球冠面积下界 |
|---|---|---|---|---|
| 4 | 70.5288° | **70.5288°**（命中正四面体最优） | 0 | 60.0000° |
| 6 | 54.7356° | **54.7356°**（命中正八面体最优） | 0 | 48.1897° |
| 12 | 37.3774° | **37.3774°**（命中正二十面体最优） | 0 | 33.5573° |
| 20 | 31.1164° | **30.0942°** | +1.02° | 25.8419° |
| 40 | 22.8669° | **21.2952°** | +1.57° | 18.1949° |
| 60 | 18.4604° | **17.3029°** | +1.16° | 14.8351° |
| 100 | 14.4389° | **13.7387°** | +0.70° | 11.4783° |
| 200 | 10.3332° | **9.4348°** | +0.90° | 8.1096° |

修正前有一个很明显的症状：40 组里有 **21 组**的 `cover` 构型，其 `R_cov` 反而不是
三个目标里最小的，甚至比 `energy` 构型还差——这说明当时"覆盖目标"并没有真的在
最小化覆盖半径。

> **为什么"能量最低"看起来也能把覆盖半径压得很小？**
> 因为两者有相关性但不相同：设 `D = max_{i<j} angle(p_i,p_j)`（点集直径），
> 恒有 `R_cov ≥ D/2`。能量最小化会把点推开、降低所有近距对，间接压小 `D`，
> 于是覆盖半径也跟着变小 —— 但它**优化的是能量的和**，不是最坏的那一个方向。
> 所以能量解常常"接近"覆盖最优，却不会最优；一旦覆盖那一栏挂的是
> 最小化均方距离的 Lloyd，就会出现"能量解反而更好"的假象。
> 现在覆盖目标走 k-center（直接最小化最大距离），这个假象就消失了。

现在的 k-center 局部搜索：

* 每个 site 取自己 Voronoi 胞腔内**并列最远**的顶点/棱中点的**平均方向**作为移动方向。
  用"单个最远点"是不行的：正八面体/正二十面体本身已是局部最优，朝单个顶点移动
  会破坏对称性（实测 `R_cov` 从 54.736° 恶化到 73°）；取平均时并列方向互相抵消，
  于是能正确判定"已到局部最优"并停住。
* 每一轮扫描后用**精确 `R_cov` 做整轮回退**，因此 `R_cov` 单调不增。
* 卡在局部极小时用逃逸候选（单点最远方向扰断 / 一步 Lloyd / 一步能量精修），
  仍然只用精确 `R_cov` 判定是否采纳。
* 最后把所有候选（能量多起点、Tammes、Lloyd、k-center）统一评估取最小——
  所以 `sphere_data.js` 里 `cover` 的 `R_cov` **有保证**不差于任何被评估的候选。

回归测试见 `python test.py` 的第 4 节：检查小 N 是否命中可解析最优、是否每组 `cover` 都最小、
以及 `R_cov` 是否都不低于球冠面积下界 `arccos(1-2/N)`。

**网页端也实现了同一套 k-center**（`sphere_uniform.html` 里的 `kcenterScanFast` /
`kcenterEscapeCheap`），为了能实时迭代做了三处工程化：

* 每帧只做"一轮扫描 + 最多 3 次步长回退"，保证单帧成本可控；
* 停滞时才做廉价逃逸（只看覆盖最差的 6 个 site 的单个最远方向，约 6 次 `R_cov` 评估）；
* 再停滞就插入随机重启，并把**历史最好**（`kBest`）一直保留 —— 所以 R_cov 单调不增。
* n > 150 时精确 Voronoi 太贵，自动退化为"斐波那契格点上最坏方向"的版本。

网页实测（从斐波那契初值出发，n≤150 走精确模式；120 步）：

| N | 网页 k-center | 网页 Frank–Wolfe | Python 数据（最优） | 单步中位耗时 |
|---|---|---|---|---|
| 6 | **54.85°** | 54.7358° | 54.7356° | 0.6 ms |
| 12 | **40.74°** | 37.3780° | 37.3774° | 6.5 ms |
| 20 | **30.66°** | 33.2526° | 30.0942° | 70 ms |
| 32 | **24.65°** | 25.52° | 22.6948° | 168 ms |
| 60 | **17.87°** | 17.86° | 17.3029° | 373 ms |
| 200（格点模式） | 9.88° | — | 9.4614° | — |

即网页端**单调下降**且多数情况下不差于能量算法；要拿最优值就用预计算解
（目标选"覆盖最小"时默认加载的就是它）。单步耗时约 0.05·n² 微秒量级，
所以点数大时迭代会变慢（界面按点数自动缩放每帧步数）。

## 3. 正确性自检

```bash
python test.py                 # Python 全量自检（几何/梯度/三类目标/覆盖回归）
```

自检覆盖：

* **解析值对照**：正四面体/正八面体/正二十面体/立方体的覆盖半径与最小夹角，
  以及 Voronoi 胞腔顶点数（3/4/5/3）。
* **梯度对照**：`riesz_energy` 的解析梯度与中心差分逐点对照（相对误差 < 1e-8），
  `d_min` 的次梯度同样对照。
* **已知最优值**：Riesz s=1 能量（N=4…20）与 Tammes 最优夹角（N=4…24, 32）的达成率。
* **面积目标**：胞腔面积总和恒为 `4π`；正八面体/立方体/正二十面体的胞腔面积全相等
  （`cv≈0`）；`area_lloyd` 的 `cv` 单调不增；数据里 `area` 构型的 `cv` 最小。
* **覆盖优化单调改善**：k-center 迭代必须让精确 `R_cov` 下降（逐步断言"上升 0 次"），
  并与 30 万点细网格给出的下界比较（下界应略小于精确值）。
* **边界情形**：N=1,2,3（退化胞腔为半球，`R_cov` = 90°）不抛异常。
* **前端一致性**（`node verify_frontend.js math`）：把页面里的数学函数抽出来，
  与 `tests/reference.json` 中由 Python 精确算出的值逐项比对（正多面体解析值、
  各 s 的能量与梯度、40 组数据的能量/夹角/覆盖半径、Voronoi 胞腔顶点数）。
* **页面行为**（`node verify_frontend.js page`）：用 DOM+canvas 桩真实执行整段页面
  脚本，覆盖 boot、首次渲染、拖动/滚轮/窗口缩放重绘、四种迭代算法、k-center 单调性、
  切目标与面板一致、自定义点数（137/900/5000/非法输入）、保存加载收藏夹、
  单步与推进 n 步、全部渲染分支（含 N=1500）。

## 4. 用法

```bash
# 求解若干 N（同时给出三类目标），输出 JSON
python sphoptim.py 6 12 20 -o out.json

# 生成网页用的完整数据集（覆盖 4–200 的一组常用取值）
python make_data.py
```

浏览器打开 `sphere_uniform.html`：

* **点数 N**：滑块 4–2000，另有"自定义 N"输入框（可到 20000，回车或点"生成"）。
  有预计算数据的 N 直接用最优解，没有的就用斐波那契格点做初值；
* **目标**：能量 / 间距 / 覆盖 / **面积均匀** 四选一；
  **来源**：预计算解 / 斐波那契初值；
* **指数 s**：下拉选 1 / 0（对数）/ 2 / 3 / 6 / 12，也可直接填任意数值（−20…50）。
  注意预计算数据是 `s=1` 的解，切到别的 s 后需要自己迭代（界面会提示）；
* **单步 / 推进 n 步**：`单步 ▸` 只走一轮，右侧可填步数后点"推进 n 步"一次走多轮
  （手动推进时会先暂停自动循环，方便逐步观察点的移动）；
* **开始迭代**后可实时看到算法把点重新分布，浏览器里有 4 个算法可选：

  | 算法 | 目标 | 说明 |
  |---|---|---|
  | **自动** | 跟随当前目标 | 选"能量"→Frank–Wolfe，"间距"→次梯度上升，"覆盖"→k-center |
  | Frank–Wolfe | 能量最小 | 球面 FW + 线搜索 |
  | 次梯度上升 | 最小间距最大 | `d_min` 次梯度上升 |
  | **k-center** | 覆盖半径最小 | 朝胞腔内"并列最远点平均方向"走，整轮精确回退 + 逃逸 + 随机重启 |
  | **加权 Lloyd** | 面积最均匀 | 朝胞腔质心走，权重 `∝ Ā/A_i`，整轮 `cv` 回退 |
  | 球面 Lloyd | （对照） | 最小化**均方距离**（k-means）。它**不是**覆盖目标，只作对照 |

  注意：覆盖半径是 **k-center（最小化最大距离）**，Lloyd 最小化的是**均方距离**，
  两者不等价——这就是"用能量/间距算法跑出来的构型，覆盖半径反而比覆盖算法更小"
  的原因（当时覆盖那一栏挂的是 Lloyd）。现在覆盖目标默认走 k-center。
* 实时指标：能量 `E`、最小夹角 `d_min`、覆盖半径 `R_cov`（前端实现了同一套球面
  Voronoi，因此是精确值；N>400 时自动改用格点估计并显示 `≈`），并画出迭代曲线；
* 着色可选"最邻点距离"或"Voronoi 胞腔面积"——均匀分布时着色应接近一致；
* 可叠加显示 ±`R_cov` 的覆盖球冠，直观看出"覆盖"与"间距"两种均匀性的差别；
* 拖动旋转 / 滚轮缩放都是**实时重绘**（按需 rAF 调度，同一帧内多次请求合并成一帧）。

## 5. 复杂度

* 能量/`d_min` 及其梯度：`O(n²)`。
* `voronoi_cells`：`O(n²)`（每个 site 只跟最近的 `k_nbr` 个邻居配对）。
* `coverage_lloyd` 每次迭代：`O(n²)`～`O(n³)`；N=60 约 10 s，N=100 数十秒。
* make_data.py 对大 N 自动减少 Lloyd 轮数（N≤40 用 200 轮，N=200 用 45 轮），
  否则 N=200 单组要十几分钟。
* 前端：N≤300 时能量/间距迭代可 60 fps；Lloyd 走 3000–8000 个斐波那契格点的
  离散版本，用来实时演示覆盖优化。
* 前端的大 N 优化（N=900 实测单步耗时）：

  | 环节 | 优化前 | 优化后 | 做法 |
  |---|---|---|---|
  | Frank–Wolfe 一步 | 1796 ms | **274 ms** | 线搜索的候选 t 与细化次数随 n 递减（每次候选都要一次 O(n²) 能量） |
  | Lloyd 一步 | 20066 ms | **68 ms** | 迭代中只算格点覆盖半径；精确 R_cov 是 O(n³)，不能放进每步 |
  | 渲染 | — | — | 网格采样数、点半径、逐点描边、着色方式按点数自适应 |

* 因此前端把"精确 R_cov"限制在 N≤400；更大的 N 用斐波那契格点估计（界面显示 `≈`）。

## 6. "均匀分布"的其他定义（备选目标）

前 4 类目标是文献里最主流的，但"均匀"在数学上还有这些**互不相同**的定义。
它们的最优构型**一般互不相同**，所以"用哪个"取决于你拿这 N 个点做什么。

### A. 能量族（按点间相互作用）

| 定义 | 目标函数 | 特点 | 状态 |
|---|---|---|---|
| **Riesz s-能量** | `Σ_{i<j} ‖p_i−p_j‖^{−s}` | `s` 可调 | 已实现 |
| **对数能量** | `Σ ln(1/‖p_i−p_j‖)` | `s=0` 的等价形式 | 已实现 |
| **高斯核 (RBF) 能量** | `Σ exp(−d²/σ²)` | 局部排斥，尺度由 σ 控制 | 备选 |
| **空腔势能 / Lennard-Jones** | `Σ (R/r_ij)^12` | 更硬的排斥，近似 Tammes | 备选 |

### B. 几何填充 / 覆盖族

| 定义 | 目标函数 | 特点 | 状态 |
|---|---|---|---|
| **Tammes（最小间距最大）** | `max min_{i<j} d_ij` | 经典 packing | 已实现 |
| **覆盖半径最小** | `min max_x min_i angle(x,p_i)` | k-center | 已实现 |
| **Voronoi 面积均匀** | `min std(A_i)/Ā` | 最贴近"等面积"直觉 | 已实现 |
| **第 k 近邻最大距离最小** | `min max_i (到第 k 近邻的距离)` | 鲁棒版覆盖，不被单个空洞主导 | 备选（推荐下一个） |
| **格点二次型最小** | `min Σ_i R_i²`，`R_i` 为最近邻距离方差 | 直接惩罚"某点特别挤/特别空" | 备选 |
| **不等权覆盖** | `min Σ w_i r_i` | 传感器布点等工程场景 | 备选 |

### C. 数值积分 / 测度族（"均匀" = 求积精度高）

| 定义 | 目标函数 / 约束 | 特点 | 状态 |
|---|---|---|---|
| **k-means 量化误差** | `min Σ_i ∫_{cell_i} d(x,p_i)² dx` | **就是球面 Lloyd 的目标**（页面里作对照） | 已实现（对照） |
| **球面 t-design** | `Σ_i f(p_i) = (N/4π)∫f dS`，对次数 ≤ t 的多项式成立 | **代数约束而非优化目标**，点数效率极高 | 备选（要换算法） |
| **最小化求积误差** | `max |∫f − (1/N)Σf(p_i)|` | 直接优化积分质量 | 备选 |
| **Wasserstein / 最优传输** | `W₂(P, 均匀测度)` | 全局度量，不只最近邻 | 备选（成本高） |
| **Discrepancy** | 球面 `L∞` discrepancy | 数论风格，理论界最完整 | 备选 |

### D. 四族的关系

```
能量族    ── 连续核，对所有点对按距离加权求和     → 平滑、易优化，间接影响覆盖
间距/覆盖  ── 只看"最坏的那一对/那一块"          → 非光滑，需专门算法，直接控制均匀度
面积/测度  ── 看"每点分到多少球面"与积分精度     → 最贴近"均匀 = 等面积"的直觉
设计/代数  ── 用对称性/代数约束换高阶精度        → 点数少但要求苛刻
```

### E. 若继续扩展，建议的优先级

| 优先级 | 定义 | 为什么 | 工作量 |
|---|---|---|---|
| ★★★ | 第 k 近邻最大距离最小 | 覆盖目标的鲁棒版，可直接复用现有 k-center 框架 | 小 |
| ★★☆ | 高斯核能量 `Σexp(−d²/σ²)` | 一个可调尺度 σ 分离"局部/全局均匀"，梯度好写 | 小 |
| ★★☆ | k-means 量化误差 | 页面已有 Lloyd，只需正式列为目标 | 很小 |
| ★☆☆ | 球面 t-design | 点数效率极高，但要换代数求解 | 大 |
| ★☆☆ | Wasserstein / discrepancy | 理论最完整，需要额外的传输/数值积分 | 大 |

## 7. 面积目标（第 4 个目标）的实现记录

**定义**：`A_i` 为第 i 个 Voronoi 胞腔的球面面积（`ΣA_i = 4π`），目标是最小化
`cv = std(A_i)/mean(A_i)`。

**实现分布**

| 位置 | 内容 |
|---|---|
| `sphoptim.py` | `cell_area`、`cell_areas`、`area_uniformity`、`area_lloyd`、`solve_area`；`solve_all` 增加第 4 个目标；`as_json_block` 输出 `cv` |
| `sphere_uniform.html` | 目标下拉加"面积最均匀"；算法下拉加"加权 Lloyd"；"自动"按目标选择；指标面板加"面积离散度 cv" 与对应指标页；导出 JSON 带 `areaCv` |
| `make_data.py` | 汇总表加"面积 cv"列 |
| `test.py` | 第 4 节：面积总和 == 4π、正多面体 `cv≈0`、`area_lloyd` 单调、数据里 `area` 的 `cv` 最小 |
| `verify_frontend.js` | 前端 `cellArea`/`areaCvOf` 与 Python 逐胞腔对照；页面端面积目标、算法选择、单调性、面板一致 |
| `tools.py reference` | 增加 `cell_area_ref` / `cell_cv_ref` 供前端交叉验证 |

**关键结论**

* 面积目标的收益**与点数强相关**：斐波那契格点本身已接近面积最优，
  n≥100 基本没有改善空间（n=100/200 ≈ 0%）；小 N 收益明显
  （n=4/6/12 的 `cv` 可到 0，n=8 到 6e-5，n=24 到 2e-4，n=20 降约 39%）。
* 因此求解器用**多候选（斐波那契/能量/对数能量/k-center/Tammes）+ 按 cv 择优**，
  而不是单纯跑加权 Lloyd——单靠一条下降流在格子初值上几步就停（n=12 一步即停）。
* 网页端为提高质量也用"能量解当起点"的多个候选；候选缓存**必须与点数绑定**，
  否则切换 N 时会复用上一个 N 的候选（曾导致 n=50 的点集被换成 n=20 的 20 个点，
  `cv` 假性降到 3e-6）。

## 8. 主要参数
